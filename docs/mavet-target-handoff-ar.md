# ملف تسليم مشروع Mavet Target

> **الغرض من هذا الملف:** انسخه أو أرفقه في محادثة جديدة لاستكمال تطوير المشروع دون فقدان سياق العمل. لا يحتوي الملف على كلمات مرور أو مفاتيح سرية.

## 1. ملخص تنفيذي

**Mavet Target** تطبيق Android/Expo باللغة العربية لمندوبي شركة Mavet Pharma. التطبيق يعمل بأسلوب **offline-first**؛ أي إن بيانات كل مندوب تبقى محلياً على هاتفه ولا يحتاج تسجيل دخول أو اتصال إنترنت في الاستعمال اليومي. يتيح التطبيق تقسيم تارجت ربع سنوي، وتسجيل البيع والتحصيل، وإدارة العملاء والمنتجات والمخزون والخزنة والعمولات، وتصدير التقارير والنسخ الاحتياطي محلياً.

| البند | القيمة الحالية |
|---|---|
| اسم التطبيق | `Mavet Target` |
| لغة وتجربة الاستخدام | العربية، RTL، وأرقام إنجليزية بفواصل آلاف |
| نوع المشروع | Expo / React Native / TypeScript |
| إصدار التطبيق | `1.0.3` |
| Android package | `com.mavetpharma.mavettarget` |
| مسار المشروع | `/home/ubuntu/mavet-target` |
| المستودع | `https://github.com/drvetmalek-bit/mavet-target.` |
| ملاحظة مهمة | اسم المستودع ينتهي بنقطة: `mavet-target.` |

## 2. الوصول إلى نسخة Android قابلة للتثبيت

تم إنشاء ملف APK موقّع وقابل للتثبيت مباشرة على هواتف Android. افتح الرابط التالي من الهاتف أو الكمبيوتر:

**[صفحة بناء APK البديل المتحقق من توقيعه](https://github.com/drvetmalek-bit/mavet-target./actions/runs/32775044240)**

بعد فتح الصفحة، انزل إلى قسم **Artifacts** ونزّل الملف المسمى `mavet-target-release-apk`. فك ضغط الملف؛ ستجد داخله `app-release.apk` بحجم تقريبي 27 MB.

### خطوات تثبيت التطبيق على الهاتف

1. انقل `app-release.apk` إلى هاتف Android، أو نزّله مباشرة من الهاتف بعد تسجيل الدخول إلى GitHub.
2. اضغط على الملف من مدير الملفات أو مجلد التنزيلات.
3. إن ظهرت رسالة حظر، اختر **Settings / الإعدادات** واسمح بالتثبيت من المتصفح أو مدير الملفات المستخدم.
4. ارجع للملف واضغط **Install / تثبيت**.
5. افتح **Mavet Target** وأدخل بيانات المندوب والتارجت من داخل التطبيق.

إذا ظهر أن Android يريد تحديث نسخة سابقة ثم رفض التثبيت، لا تحاول تحديث النسخة القديمة. خذ نسخة احتياطية من داخل التطبيق القديم أولاً إذا كانت به بيانات، ثم احذف النسخة القديمة وثبّت هذا الـ APK البديل. يستخدم البديل هوية Android مستقلة (`com.mavetpharma.mavettarget`) وقد اجتاز فحص توقيع APK أثناء البناء.

> ملفات Artifacts في GitHub محفوظة لمدة 30 يوماً في الإعداد الحالي. عند انتهاء المدة أو الحاجة إلى نسخة أحدث، شغّل مسار **Build Android APK** من تبويب Actions في المستودع، ثم حمّل الـ Artifact الجديد.

## 4. قواعد العمل المهمة

### التارجت والكمية

يخزن كل منتج `quantityTarget`. القيمة `0` تعني أنه لا يوجد تارجت وحدات مفعل. توجد شاشة إعداد مستقلة باسم **تارجت المنتجات** لتعديل تارجت وحدات كل المنتجات دفعة واحدة، ولا تغيّر السعر أو العبوة أو بيانات المنتج الأخرى.

### الأرقام والتنسيق

كل الأرقام المعروضة تستخدم أرقاماً إنجليزية وفواصل آلاف. الدالتان `currency()` و`quantityFormat()` في `lib/target-data.ts` تستعملان `Intl.NumberFormat("en-US")`.

### المخزون

آخر جرد هو مصدر الرصيد المعروض. عند تسجيل بيع مرتبط بمنتج موجود في الجرد، ينقص رصيد المخزون تلقائياً؛ وعند حذف البيع، يعود الرصيد المرتبط به.

### العمولات

| العمولة | القاعدة |
|---|---|
| عمولة البيع | `1%` من محقق البيع، ولا تظهر إلا إذا كان البيع والتحصيل كلاهما `80%` أو أكثر. |
| عمولة التحصيل | `1%` من محقق التحصيل، وبنفس شرط 80% المتزامن. |
| نوبيوتيك | `25` جنيه/لتر عند 250–499 لتر، و`50` جنيه/لتر عند 500 لتر أو أكثر. لا تستحق إلا عند تغطية قيمة مبيعات نوبيوتيك بتحصيلات مرتبطة بفواتيره. |

### الخزنة

المعادلة هي:

```text
النقدية المتوقعة = الرصيد الافتتاحي + كل التحصيلات − التوريدات − المصروفات
```

## 6. تخزين البيانات والخصوصية

لا يوجد Backend أو حسابات مستخدمين أو مزامنة سحابية في الإصدار الحالي. تُخزَّن بيانات التطبيق في `AsyncStorage` تحت المفتاح `mavet-target-data-v1` من خلال `TargetProvider` في `lib/target-store.tsx`.

يشمل نموذج البيانات: المندوب، التارجتات، العملاء، المنتجات، المبيعات، التحصيلات، الرصيد الافتتاحي وحركات الخزنة، والجرد. الملف المرجعي للنماذج والتطبيع هو `lib/target-data.ts`.

> لا تعِد المستخدم بوجود نسخ سحابية تلقائية حالياً. استخدم وظيفة النسخة الاحتياطية المحلية قبل تغيير الهاتف أو مسح التطبيق.

### أسرار GitHub المطلوبة

هذه الأسرار موجودة في مستودع GitHub ولا يجب وضع قيمها في أي ملف أو محادثة:

| اسم السر | الاستخدام |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | مفتاح توقيع Android مشفراً بصيغة Base64. |
| `ANDROID_KEYSTORE_PASSWORD` | كلمة مرور ملف المفتاح. |
| `ANDROID_KEY_ALIAS` | اسم المفتاح الداخلي. |
| `ANDROID_KEY_PASSWORD` | كلمة مرور المفتاح الداخلي. |

يوجد أيضاً رمز وصول GitHub محدود بالمستودع فقط، بصلاحيات الكتابة للـ Contents وWorkflows وSecrets وActions. لا تطلب قيمته من المستخدم في محادثة، ولا تسجله في Git.

### تشغيل بناء جديد

1. افتح المستودع ثم تبويب **Actions**.
2. اختر **Build Android APK** لتثبيت مباشر على الهاتف، أو **Build Android AAB** للرفع إلى Google Play.
3. اختر **Run workflow** ثم انتظر اكتمال العملية. أول بناء قد يأخذ أكثر من عشر دقائق.
4. افتح التشغيل الناجح، ثم نزّل الـ Artifact المناسب من أسفل الصفحة.

## 9. التشغيل والتأكد محلياً

نفّذ الأوامر التالية من مسار المشروع عند الحاجة:

```bash
cd /home/ubuntu/mavet-target
pnpm install
pnpm dev
pnpm exec vitest run tests/target-metrics.test.ts tests/github-token.test.ts
pnpm check
pnpm lint
```

آخر نتيجة معروفة: **14 اختباراً ناجحاً**، و`pnpm check` ناجح، و`pnpm lint` ناجح. قد يظهر تحذير `MODULE_TYPELESS_PACKAGE_JSON` من قالب ESLint؛ لا يمنع البناء أو الاختبارات.

## 10. نقاط يجب عدم كسرها عند الاستمرار

1. حافظ على العربية وRTL، وعلى الأرقام الإنجليزية مع فواصل آلاف في كل شاشة جديدة.
2. لا تضف Login أو قاعدة بيانات أو خدمة سحابية إلا بطلب صريح؛ التطبيق مصمم ليبقى محلياً لكل مندوب.
3. لا تستخدم `className` على `Pressable`؛ استخدم `style` وفق إعدادات NativeWind الحالية.
4. استخدم `ScreenContainer` في كل شاشة جديدة.
5. لا تضع أسرار GitHub أو مفاتيح توقيع Android في Git أو في النصوص المعروضة للمستخدم.
6. لا تحذف بيانات المستخدم أو النسخ الاحتياطية أثناء التعديلات. تحقق من توافق البيانات القديمة عبر `normalizeAppData`.
7. صدّر الملفات وشاركها من الهاتف؛ المعاينة على الويب قد تعرض رسالة تفيد بأن خصائص التصدير مخصصة للجهاز.
8. خادم المعاينة قد يتوقف بسبب ضغط الذاكرة؛ أعد تشغيله عند الحاجة بدلاً من اعتبار ذلك خللاً في منطق التطبيق.
